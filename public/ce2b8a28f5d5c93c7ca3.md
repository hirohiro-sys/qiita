# はじめに
最近毎週ドメイン駆動設計についての勉強に参加しているのですが、今回は業務領域の分類を通してコアドメインや支援ドメイン、汎用ドメインについてそれぞれ学びました。この記事ではとある架空の美容室チェーンを題材として、実際にAIを使ってヒアリングを行い、業務領域の分類をした上で最終的にはドメインビジョンステートメントを整理していくワークをやっていこうと思います。

# 今回の対象範囲
勉強会はオライリーから出ている「ドメイン駆動設計をはじめよう」という本を参考に行っています。今回は第一章「事業活動を分析する」をテーマに行いました。

# 今回やること

1. 以下プロンプトをもとに、AIを使ってヒアリングを行う（20分程度）
1. ヒアリングでわかった業務内容を洗い出し、コア、支援、汎用に分類する
1. コアに分類した業務においてドメインビジョンステートメントを書く
1. 以下プロンプトをもとに、分類結果とその理由、ドメインビジョンステートメントをもとにAIからフィードバックをもらう

```ヒアリング.txt
あなたは美容室を5店舗経営している社長です。
私はシステム開発者で、新しい業務システムを作るためにヒアリングをします。
・あなたの会社が他社に勝っている本当の理由を、あなた自身で一つ設定してください。
・その理由は、聞かれない限り自分からは話さないでください。
・業務について聞かれたら、具体的なエピソードを交えて自然に答えてください。
・質問が表面的であれば、表面的な答えを返してください。
・私が「フィードバック」と入力したら、私が貼り付ける分類と文章を評価してください。
```
```フィードバック.txt
フィードバック
【分類】(業務ごとに、コア・支援・汎用のいずれかと、その理由)
【ドメインビジョンステートメント】(コアについての文章)
次の観点で評価してください。
1. 設定した本当の強みと、私が選んだコアは一致しているか
2. 分類の理由は、競争優位性・複雑さ・変わりやすさの観点から妥当か
3. ステートメントは、コアの価値を他社との違いとして言えているか
4. 強みにたどり着くために、どのような質問をすればよかったか
```

### 1. 顧客層と利用シチュエーション

**💬 エンジニア:**
普段はどのような層のお客さんがよく来ますか？

**👤 オーナー:**
うちのお店は、主に**30代から40代の働く女性**や、**小さなお子さんのいるお母様**が中心ですね。
特に平日の朝から夕方にかけては、子育ての合間や仕事のシフト前後に来られる方が多い印象です。土日になると、ご家族やご夫婦で一緒にいらっしゃるケースもよく見られますよ。

**💬 エンジニア:**
なるほど。若者向けというよりは、時間に追われている女性がメインターゲットという感じですか？

**👤 オーナー:**
そうですね、まさにその通りです。家事や仕事で忙しい合間を縫って来てくださるお客様がほとんどなので、**「限られた時間の中でしっかりリフレッシュして綺麗になっていただきたい」**という思いで営業しています。

例えばこの間も、平日の昼間に常連の30代のお母様がいらして、「子供を預けられる時間が2時間しかなくて、その間にカラーとトリートメント、前髪カットまで全部終わらせたい！」とおっしゃっていて。スタッフが手際よく同時並行で進めて、なんとか時間ぴったりに仕上げたらすごく喜んでいただけました。そういったバタバタした日常の中で、少しでもホッとできる場所でありたいと思っています。

---

### 2. 施術スピードと時間の比較

**💬 エンジニア:**
カラーやトリートメント、前髪カットまでをその短い時間で提供できているのは大きな強みですね。一般的な美容室だと、どれくらい時間がかかるものなのですか？

**👤 オーナー:**
一般的な美容室だと、カウンセリングから始まって、カラー（塗布と放置時間で約1時間）、トリートメント（15〜20分）、シャンプー・ブロー、前髪カットまで合わせると、**トータルで2時間から2時間半ほど**かかるのが標準的かと思います。施術工程ごとにしっかり時間を取るサロンが多いですね。

うちの場合は、お客様が希望される退店時間を最初にお伺いして、それに合わせて工程を組み立てたり、手の空いているスタッフがアシストに入って2人体制で塗布を進めたりして効率化を図っています。

---

### 3. 予約枠の組み方と待ち時間への配慮

**💬 エンジニア:**
平日に来られる方が多いとのことですが、お客さんの待ち時間が発生したりはしないのですか？予約システムなどは導入されていますか？

**👤 オーナー:**
もちろんWeb予約システムを導入しているので、基本的には事前予約のお客様が中心です。ですが、平日昼間の忙しいお母様方や働く女性は、「急に1時間だけ時間ができた」とか「子供が急に熱を出して時間をずらしたい」といった予定変更がどうしても起きやすいんですよね。

そのため、予約枠をキチキチに詰めるのではなく、**そうした突発的なご来店や予約の前後変更にも柔軟に対応できるよう枠の組み方を工夫**しています。

ただ、特定の時間帯（午前11時頃や午後2時頃など）に前の施術の終了と次のお客様の受付が重なると、受付で5分〜10分ほどお待ちいただくことはありますね。この前も飛び込みの常連様に10分ほどお待ちいただき、お茶をお出ししながら対応しました。お待たせする時間もできる限り短く収めるよう意識しています。

---

### 4. 柔軟な現場対応とコミュニケーションの工夫

**💬 エンジニア:**
突発的な来店や予約変更に柔軟に対応する具体的な仕組みや、待ち時間を短く感じさせる工夫について詳しく教えてください。

**👤 オーナー:**
一番の理由は、**現場スタッフ同士のインカム（小型トランシーバー）による情報共有**ですね。

お客様がご来店された際や電話でのお申し出があったタイミングで、すぐ全スタッフがインカムで「〇〇様、30分前倒しでご来店です。カラー放置中のスタイリストでヘルプに入れませんか？」とリアルタイムに声を掛け合います。手の空いているスタッフがアシストに入ったり事前準備を済ませたりして、隙間時間にスムーズに組み込んでいます。スタイリスト個人任せにせず、店舗全体で動くスタイルです。

また、お客様を退屈させない工夫としては、カット台に座ってからの**「放置される時間」を無くすこと**を最重視しています。待ち時間が発生しそうな場合は「いま前の工程が伸びており、〇分には開始できます」と見通しを明確にお伝えし、電子書籍（タブレット）をお渡ししたり、カウンセリングだけ先に進めたりして、「ただ何もせず待つ」状態を作らないようにしています。

---

### 5. チームオペレーションへのこだわり

**💬 エンジニア:**
小型トランシーバーでのリアルタイム共有に加え、コミュニケーションを密にして放置感を与えない工夫は非常に素晴らしいですね。

**👤 オーナー:**
ありがとうございます。うちの現場では**「どれだけ良い技術があっても、お客様に『待たされている』『ほらかしにされている』と感じさせてしまったら台無しだ」**という考えが浸透しているんです。

インカムでのリアルタイム共有も、お客様の前でバタバタ連絡を取り合うのではなく、スマートに連携して表面上は穏やかで落ち着いた接客を維持するために導入しました。こうした現場の動きや丁寧なコミュニケーションが、店舗の雰囲気を支えています。

---

### 6. 価格帯と客単価

**💬 エンジニア:**
料金設定はどのようになっていますか？

**👤 オーナー:**
地域相場からすると「平均より少し高め」に設定しています。
具体的には以下の通りです。

- **カット:** 5,500円〜
- **カット＋カラー＋トリートメント:** 14,000円〜18,000円程度
- **平均客単価:** 12,000円前後

低価格のファストサロンではありませんが、都心の最高級サロンほど高額でもありません。30〜40代の女性が「自分へのちょっとしたご褒美」として無理なく通える絶妙なラインを意識しています。

---

### 7. 美容師の普段の業務フロー

**💬 エンジニア:**
美容師さんたちの普段の業務内容・1日の流れを教えていただけますか？

**👤 オーナー:**
基本的な1日の流れは以下の通りです。

| 時間帯 | 業務内容 | 詳細・工夫 |
| :--- | :--- | :--- |
| **朝（出勤〜開店）** | 清掃・準備・朝礼 | インカムで本日の予約状況や注意点（カルテ共有）を確認 |
| **営業中** | 施術・接客・インカム連携 | 退店希望時間の確認、アシストヘルプでの複数人施工、リアルタイム進行確認 |
| **隙間時間** | カルテ入力・消毒・清掃 | カラーレシピ記録、道具の消毒、セット面清掃 |
| **閉店後** | 終礼・レジ締め・トレーニング | 売上確認、若手・アシスタントの技術練習 |

施術だけでなく「清掃・準備」「カルテ管理」「スタッフ間連携」が業務の大半を占めています。

---

### 8. システム導入状況と課題（予約・備品・会計・カルテ）

**💬 エンジニア:**
備品管理や予約管理、カルテなどにはどのようなアプリケーションやツールを利用していますか？また、お会計は店舗で行っていますか？

**👤 オーナー:**
各業務の管理状況は以下のようになっています。

:::note warn
**各システムの運用状況と課題**

- **予約管理・会計（市販POSシステム）**
  - Web/アプリからの24時間予約、レジ機能、売上集計、シフト連動に対応。会計は施術後に店頭レジで実施。
- **備品・在庫管理（手作業・アナログ）**
  - 目視でチェックし、ノートに手書き記入後、FAXやWebサイトで注文。**カラー剤の在庫切れが発生し、近隣店舗に走って借りに行くのが課題**。
- **カルテ管理（POS内電子カルテ）**
  - 使用薬剤のレシピ、放置時間、会話の好み、仕上げ写真を記録。**忙しい時間帯は入力が営業後になり、記憶があやふやになったり遅れたりするのが課題**。
:::

</details>

# 2. 業務領域の分類


| ドメイン種別 | 対象業務 | 分類理由 |
| :--- | :--- | :--- |
| **コアドメイン** | リアルタイム現場連携・待ち時間コントロール | インカム活用で顧客の「放置感」をなくし、タイムパフォーマンスを高めるCX（顧客体験）が最大の強みであるため |
| **支援ドメイン** | 顧客カルテ・施術履歴管理 | 次回以降の高品質な施術に不可欠だが、一般的なサロンでも電子カルテで管理されているため |
| **汎用ドメイン** | POSレジ・予約・備品在庫管理 | 市販のSaaSやパッケージ、手作業で代替・運用可能であるため |

# 3. ドメインビジョンステートメントの整理
ドメインビジョンステートメントとは、エリック・エヴァンスの本で蒸留手法の一つとして挙げられているもので、コアドメインがどのような価値をもたらすのかを簡潔に記述したものです。

今回のヒアリング結果からは以下のように整理できました。

```
「インカムを用いたリアルタイムな動態可視化とチーム連携により、多忙な顧客の限られた滞在時間で
『無駄な待ち時間ゼロ』と『落ち着いた上質な接客』を両立する。」

個人の勘や個別のスタイリストの進捗に頼っていた従来のサロンワークから脱却し、
店舗全体で突発的なスケジュール変化へ柔軟に対応できるオペレーション構造を確立する。
これにより、「1分1秒も無駄にされず、かつ温かい気配りに包まれる」という、
一般的な美容室の待ち時間ストレスを完全に解消した唯一無二のタイムパフォーマンス体験を提供する。
```

### 設定していた自社の本当の強み

「施術レシピ・工程データ（調合・放置時間・骨格別の施術ステップ）の徹底した標準化・共有による、どのスタイリストが担当してもブレない超高速・高品質な施術再現力」
（忙しい30〜40代女性が『誰に当たっても絶対に短時間で理想通りになる』という安心感・再現性が高単価と高リピート率の本質的な勝因という設定でした）

---

### 観点別フィードバック・評価

#### 1. 設定した本当の強みと、選んだコアの一致度
* 評価：不一致（手段・オペレーションへの着眼にとどまった）
* 分析：
  * 今回選定されたコア（リアルタイム現場連携と待ち時間コントロール）は、ヒアリングで表面に出てきたインカム活用や待ち時間短縮という「運用の工夫（手段）」にフォーカスが当たっていました。
  * 裏の強みは「施術データ（レシピ）の標準化と共有による技術の完全再現性・高速化」であり、現場連携や待ち時間短縮はその標準化されたデータ基盤があるからこそ成り立っていた、という構造です。

#### 2. 分類の妥当性（競争優位性・複雑さ・変わりやすさの観点）
* 評価：論理的で筋は通っているが、本質的な競争優位性の観点では逆転している
* 分析：
  * 現場連携・オペレーション（コアと定義）： 「顧客体験（CX）を高める」という点では優位性のロジックが通っていますが、運用の複雑さや仕組み化の観点では本来支援ドメインに近い領域です。
  * カルテ・施術履歴管理（支援と定義）： 一般的なサロンでは支援ドメインですが、当サロンの本当の強み（レシピの標準化・誰でも再現できる仕組み）においては、こここそがコアドメイン（競争優位性の源泉）にあたります。
  * 予約・レジ・在庫（汎用と定義）： 外部SaaSや市販POSで代替可能という判断は、業界標準や変わりやすさの観点から非常に妥当です。

#### 3. ステートメントの評価（コアの価値・他社との違い）
* 評価：業務の価値（時間の尊重と顧客体験）は書けているが、「真似できない他社との違い」としては弱め
* 分析：
  * 「機能を並べず業務価値を書く」「1段落程度にまとめる」というルールは綺麗にクリアできています。
  * ただし、「インカムを使ってチームで待ち時間を減らす」という運用自体は他社でも物理的に真似が容易なため、持続的な差別化（Moat）を提示するステートメントとしては、やや表面的なオペレーション要素にとどまってしまいました。

#### 4. 強みにたどり着くために、どのような質問をすればよかったか？
表面的なオペレーション（インカムや時間調整）で満足せず、「なぜそれが可能なのか？」「なぜスタイリストごとのブレや遅れが出ないのか？」というバックヤードの構造を深掘りする質問が必要でした。

効果的だった質問例：
1. 再現性・属人化への深掘り
   * 「ヘルプが入ったり担当が変わったりしても、仕上がりの品質や時間にブレが出ないのはなぜですか？」
   * 「急なアサイン変更でも、全員が同じペースで施術を進められる仕組みがあるのですか？」
2. 時間の短縮理由の深掘り
   * 「他店より施術時間を短縮できているとのことですが、単に手を早く動かしているだけですか？それとも工程自体を効率化しているのですか？」
3. カルテ・データの活用についての深掘り
   * 「カルテに記録しているカラーレシピや放置時間は、現場のスピードや共有にどう活用されていますか？」

---

### まとめ
ドメインヒアリングでは、ドメインエキスパート（オーナー）が語る「目立つ運用の工夫（インカムや気配り）」に引っ張られず、その裏でビジネスを支えている「ソフトウェア化すべき本質的な知見・構造（データの標準化）」を見抜くことが最も難しく、重要なポイントとなります。

# 気づき

### すぐに判断を確定させない
先ほどのヒアリングでは、インカム等を利用した密なリアルタイムコミュニケーションをしているということを聞き、コアドメインはそれに付随する柔軟な接客対応ができていることだと早い段階で判断してしまいました。しかし実際は施術内容や工程の標準化、共有構造がシステムで明確に実現されており、それらのデータにより美容師の経験やお客さんの要望に関わらず一貫した品質と速度で施術ができるというのがコアの部分でした。今回はヒアリング時間を20分程度としたのもありますが、もう少し表面的な運用方法だけでなく時間に追われているお客さんのニーズに対応できている理由を深ぼっていく必要があったなと思いましす。

### 業務内容を理解するには綿密なコミュニケーションが必要
このワークの話ではないのですが、勉強会でも別テーマで同じワークをチームでやりました。特定の業務がコアなのか支援なのか等を話し合うのですが、人によってその業務（フードデリバリーの場合、通知や注文の受付など）が指すスコープや登場人物の認識が若干異なり、一つの業務を分類するのにも結構時間がかかりました。この辺りはやはりメンバーやドメインエキスパート間でしっかりコミュニケーションを取る必要があると思いますし、本来はユビキタス言語や境界付けられたコンテキストを基に会話したほうがいいのかなとも思いました。

### コアドメインを知ることでどこに投資すべきか判断できる
例えば配達速度を重視ているフードデリバリーチェーンの場合は注文と配達員をマッチングさせる業務がコアドメインとなり、実際にそのアルゴリズムを開発するエンジニアのリソースが重要になります。一方、配達速度ではなく、そのフードデリバリー店だからこそ扱える店舗や料理があることをコアドメインとする場合、加盟店を開拓する営業などのリソースがエンジニアより重要になってきます。同じ事業活動をしていても、何がコアドメインかで自社で内製するのか外部ツールを利用するかなどの選択が大きく異なってくるのが面白いなと思いましたし、開発文脈でも何が重要なロジック・データなのかを知ることで技術への落とし込み方も変わってくるなと思いました。
